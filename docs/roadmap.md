# Roadmap

## Phase 1 – arena prototype (current)

**Goal:** answer one question – *Are combat and progression fun, and not too complicated?*
Local, in **host mode** (listen server with a second client window). Client and server
are separated from the start, so online play later does not need a rewrite. **Humanoid and
slime** are both in: the humanoid tests positional combat with weapons, the slime tests
evolution and the monster side. Every milestone ends with something playable.

Rough estimate: 4–6 weeks of regular work (uncertain: animation and tuning cost more than
pure logic).

### M1 – Foundation (2–3 days)

- [x] Unreal project from text files (`.uproject`, `Config/`, `Source/Hydra/`), C++ module,
      Enhanced Input. Build from the command line.
- [x] Values subsystem: load `data/values.json`, reload with `Hydra.ReloadValues`;
      automation test that every key is mapped.
- [x] Data files with stable IDs for forms, skills, elements and weapons (first entries
      only: humanoid, slime, longsword, shield, fire).
- [x] Small helper layer over GAS (native effects, SetByCaller values, native tags).
- [x] Host mode with a second client window; network emulation switchable (latency steps,
      packet loss).
- [x] Empty arena with a few obstacles (generated by script or C++).
- [x] Third-person camera, soft aim assist and lock-on (lock-on turns only the camera).
- [x] Stamina (max, regeneration, regeneration delay).
- [x] `Scripts/run_tests.sh` (build + automation tests) and a scripted live run
      (host + client, automated input, screenshots).

### M2 – Combat core, humanoid (1–2 weeks)

- [x] Longsword and shield; one button per hand; light and heavy attack; chains; interrupt
      by weight; weight costs stamina.
- [x] Directional block (arc per shield), dodge as pure movement without invulnerability,
      rebound on the attacker, clear telegraphs (long wind-ups for heavy attacks).
- [x] Turn rate from weight ÷ strength (with floor and cap; slower while blocking and
      attacking).
- [x] Weak points (back) instead of random crits.
- [x] **Hit detection with lag compensation** (rewind for melee hits and the block arc) –
      built early and tested with simulated latency.
- [x] Simple AI opponent for practice (same rules as players).

### M3 – Slime and magic (about 1 week)

- [x] Blender pipeline by script: model, rig, procedural textures baked by script, FBX
      export with fixed settings for Unreal; import path for animations made by the human
      (`docs/tech/blender-pipeline.md`).
- [x] **"Models by script" test:** build, rig, texture and export the slime agentically and
      make it playable (placeholder animations by script until the human's animations
      exist); the wolf pup only as a pipeline test (model, rig, texture, not playable) – is
      the topology good enough for animation?
- [x] Slime: slam and projectile; mana.
- [x] Minimal magic (slime only; the humanoid stays physical in Phase 1): fire bolt, fire
      element field with the burning debuff.

### M4 – Progression and waves (about 1 week)

- [x] Character level, skill XP by use, one imprint; start at fixed levels.
- [x] Evolution to the fire elemental slime with an instinct.
- [x] AI enemies in waves, same rules as players (reaction time and error rate per enemy).
      Some deal fire damage – the slime's path to its fire imprint.
- [x] Metrics (hits, blocked hits, dodges, stamina use) as CSV for later tuning.

### M4b – Align with the attribute model (2–4 days)

Decision 2026-11-17: Phase 1 takes over the concrete attribute model before the playtest,
so the playtest tests the rules that stay. Rules and formulas: `docs/design/phase-1.md` §26.

- [ ] Body attributes per form, growing 2 % of the base per level; HP, stamina and mana
      10 per point; no direct HP or damage bonus per level.
- [ ] Costs only from weight ÷ body weight (× demand); regeneration as a share per form, none
      during an action; skills no longer lower costs.
- [ ] Damage with added-up progress bonuses (skill, strength or dexterity, imprint) and
      multiplied situational factors; weak point by dexterity; resistances as points with a
      curve.
- [ ] Block: holding cost per second, block cost and rebound as shares of the blocked damage;
      interrupt by a share of maximum HP.
- [ ] Dodge and jump as capabilities: no dodge skill; dodge distance and speed by dexterity.
- [ ] Numbers rescaled (values.json), all live runs green; tables in `phase-1.md` §23–§25
      updated to what was built.

### M5 – Look and playtest (a few days)

- [ ] **Decide the look** based on our own models (toon or not – still open), and with it how
      much texture work is needed (procedural only, or hand-painted detail as well).
- [ ] Decide which placeholder animations are replaced first by the human's own animations
      (combat animations first: they carry the telegraphs).
- [ ] Playtest: Are combat and progression fun? Is it too complicated?

**Not in Phase 1:** online play over real servers and a source-built engine, reserve, hand
and magic wheels, augments, more weapons and elements, wolf and saurian as playable forms
(all Phase 1b); bushes, stealth and perception (Phase 2); menus beyond the bare minimum,
real sound (placeholders only), Steam Deck.

**Done when:** you can play 10–15 minutes against waves as a humanoid or as a slime, level
up or evolve once on the way, and the metrics deliver first numbers.

## Later phases (overview)

Full checklists: [`design/later-phases.md`](design/later-phases.md).

- **Phase 1b – arena complete:** online over real servers (source-built engine), PvP
  humanoid vs. monster, server settings for private servers, spear and short bow, free
  choice of hands, ice as opposing element, more spell forms, hand and magic wheels,
  augments with bound mana, starting forms of wolf and saurian, threat rating and hXP,
  groups and reviving, dungeon mode with a boss, matchmaking, first balancing numbers,
  alpha.
- **Phase 2 – fixed maps on dedicated servers:** world, survival, camp and nest, reserve,
  exploring, stealth and sight cover, crafting, armor, full level system, veteran levels,
  travelling merchants, factions and reputation, dungeons in the world, unlocking species,
  mod support, monetization decision.
- **Phase 3 – MMO:** persistent large world, changing landscape (building sites with states
  and tiers), strategy layer (territories, seals, war), unique items.
